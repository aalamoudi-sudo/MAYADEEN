# تقرير تنفيذ تصعيد المهام المتأخرة

## القالب المعتمد

وجدت الإرسال الفعلي للمهام المستعجلة في `apps-script/Code.gs` داخل `sendUrgentTaskNotifications` ثم `sendUrgentTaskEmail_`. القالب الحالي **نصي بسيط** ولا يحتوي شعارًا أو ترويسة HTML أو بطاقات أو زر إجراء أو CSS؛ يستخدم اتجاه عميل البريد الافتراضي، والنص الثابت يختم بـ«فريق الدعم والخدمات».

تم استخراج النص الأصلي إلى `buildUrgentTaskEmailBody_` من دون تغيير مخرجات أو شكل بريد المهام المستعجلة. يستخدم بريد التصعيد نفس أسلوب القالب النصي، ويغلف النص نفسه للعرض والإرسال في حاوية RTL بخطوط Arial/Tahoma فقط كي تكون معاينة HTML مطابقة فعليًا إلى `htmlBody` المرسل، لا تصميمًا جديدًا مفترضًا.

## المعاينة التجريبية

الملف `docs/OVERDUE_ESCALATION_PREVIEW.html` يعرض To وCC وBCC وSubject والجسم الكامل بعناوين نطاق `.invalid`. لا ينفذ الملف أي JavaScript أو طلب شبكة، ولا يرسل أي بريد.

## حدود التنفيذ

لم يتم تشغيل `sendUrgentTaskNotifications`، ولم يتم استدعاء `escalate_overdue_task` على بيئة حقيقية، ولم يحدث نشر أو دمج أو إصدار Production. البريد الفعلي لأثير أو لأي مستلم لا يُخمن؛ الخادم يرفض العملية إذا كان البريد مفقودًا أو غير صالح في `User Access Matrix`.
